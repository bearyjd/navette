# M1 operator guide

M1 runs stock `wprsd` processes on the application host and stock `wprsc`
processes on a Linux client. It provides orchestration and a versioned control
API; it does not yet provide application-layer authentication or media support
for Android.

## Prerequisites

- A Wayland desktop with `XDG_RUNTIME_DIR` set.
- `wprsd` on the host and `wprsc` on every Linux client, from the stock wprs
  revision validated in the M0 report.
- Rust 1.85 or newer to build this edition-2024 workspace.
- OpenSSH when attaching from a different machine.

Build and install the two Navette executables:

```bash
cargo build --release --workspace
install -Dm755 target/release/navetted ~/.local/bin/navetted
install -Dm755 target/release/navette ~/.local/bin/navette
```

## Run the host daemon

For an interactive test:

```bash
navetted
```

The default control endpoint is `ws://127.0.0.1:9417/v1/ws`. Session state is
stored under `$XDG_STATE_HOME/navette`, with a fallback to
`~/.local/state/navette`. Private runtime sockets are stored under
`$XDG_RUNTIME_DIR/navette`.

To install the sample user service:

```bash
install -Dm644 contrib/systemd/navetted.service \
  ~/.config/systemd/user/navetted.service
systemctl --user daemon-reload
systemctl --user enable --now navetted.service
systemctl --user status navetted.service
```

If the user manager does not inherit a toolchain-managed `wprsd`, either put
it in a standard user-service `PATH` or add an absolute `--wprsd` path to the
service's `ExecStart`.

## Use the CLI locally

Desktop entry IDs come from the XDG application database. Common operations
are:

```bash
navette ls
navette run firefox --name work-browser
navette attach work-browser
navette detach work-browser
navette kill work-browser
```

`attach` runs in the foreground. It records the `wprsc` process under
`$XDG_RUNTIME_DIR/navette/clients`, so a second terminal can detach it without
killing the host application. Omitting the session from `detach` works only
when exactly one attachment is tracked.

## Connect from another Linux machine

Keep the daemon bound to loopback and forward its control port over SSH:

```bash
ssh -N -L 9417:127.0.0.1:9417 tower
```

In another terminal, control the host through the tunnel. Supplying `--ssh`
also makes `attach` forward the session's Unix socket before starting the
local `wprsc`:

```bash
navette --url ws://127.0.0.1:9417/v1/ws --ssh tower ls
navette --url ws://127.0.0.1:9417/v1/ws --ssh tower attach work-browser
```

`NAVETTE_URL` and `NAVETTE_SSH` provide the same settings as the flags.

## Network safety

M1 has no application-layer authentication. `navetted` therefore rejects a
non-loopback bind unless `--allow-remote` is also supplied. Prefer the SSH
tunnel above. If `--allow-remote` is used on a private overlay network, its
access controls are the authentication boundary; never expose the M1 endpoint
directly to an untrusted network.

## Troubleshooting

- `XDG_RUNTIME_DIR is unset`: run inside the graphical user session, or pass
  an explicit private `--runtime-dir` to the daemon.
- `wprsd did not create session sockets`: verify `wprsd` is executable and
  that its build works independently on the host.
- An app is absent: entries marked `Hidden` or `NoDisplay`, entries excluded
  from the current desktop, and entries with a missing `TryExec` are filtered.
- Attach cannot start: verify `wprsc` is installed locally. For remote attach,
  also verify public-key SSH access and OpenSSH Unix-socket forwarding.
